# Why RAMX fits AI Security & Defense

The weak point of every agent with a wallet is the agent itself: one prompt injection and it will happily pay whoever the attacker names. x402 on NEAR makes this worse, because a NEP-366 delegate signed with a full-access key can move all of an agent's USDC. RAMX does not try to make the model behave; it takes the power away. A **guarded agent** holds only a NEAR function-call key that can call `escrow.pay` on `escrow.ramx.testnet` and nothing else, and the escrow contract enforces the owner's policy on chain: an allow list of payees, a per-call maximum, a total budget and a pause switch that only the owner controls. `pnpm --filter @ramx/agent-client attack` plays a fully compromised agent and makes five attempts: pay a stranger, exceed the per-call cap, drain the budget, call the USDC contract directly with the key, and rewrite its own policy. All five are refused by the chain, not by our code, and two of the refusals are public transactions ([J4YypM…](https://testnet.nearblocks.io/txns/J4YypMMUmYSDv87xA4bAjUTTUELAaFofrzy5zS7J3hja), [EKwP6t…](https://testnet.nearblocks.io/txns/EKwP6tQZLgaHQNFS9ALqJavzjpUD73t4VrZH1TAJxTFG)), next to a legitimate guarded payment that went through and got its answer ([9gFGWr…](https://testnet.nearblocks.io/txns/9gFGWr23xEkdqPXF97T5Y5FHNgP6caHTaqA7sEyRXaPh)).

The same "don't trust, enforce" rule covers the rest of the system. An open network of laptops is an invitation to cheat, so the gateway bills `min(reported tokens, observed + 8)`, a pool that over-reports loses reliability and therefore traffic, and 10% of pool answers are sampled to a NEAR AI Cloud model in a TEE whose fresh-nonce attestation and signed verdict go on the receipt (we call it a plausibility check, not proof of correct execution); answers served by the enclave itself carry its signature over the exact request and answer, checked against an attested key. Secrets an agent pastes into a prompt, such as API or private keys, are swapped for placeholders before any untrusted laptop sees them, and an agent that needs more can encrypt its request end to end to an enclave it attested itself, so not even the RAMX gateway can read it. Earnings vest for an hour and can be clawed back, so a hit-and-run provider gains nothing. Every balance change is an ed25519-signed event appended to the ledger contract, which refuses gaps and duplicates (`first_seq`), and anyone can re-check one with `verify-event.ts <tx>`; NEP-413 logins are verified against the account's on-chain keys over RPC, and the ledger only accepts one writer. The honest limit, stated plainly: the gateway is still the party that produces the records; the chain makes them tamper-evident and auditable, and the escrow makes agent spending provably bounded.
